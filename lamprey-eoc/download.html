Before you install

Check the file, then run it

Verify the download

Open PowerShell in the folder you saved it to and run the line below, with the file name of whatever you downloaded. The output has to match that file's SHA-256 above, character for character.

Get-FileHash .\Open-Source-EOC-Setup-0.9.2.exe -Algorithm SHA256

On a Mac, in Terminal:

shasum -a 256 Open-Source-EOC-0.9.2-macOS.dmg

Expect a SmartScreen prompt

The demo isn't code-signed yet, so Windows flags the installer as an unrecognized app. Once the hash matches, choose More info, then Run anyway.

On a Mac, expect a Gatekeeper prompt

Install Postgres.app with PostgreSQL 16 into Applications first; it doesn't need to be running. Save the map data packet to Downloads, then drag Open Source EOC into Applications. The app isn't signed by an Apple developer yet, so Control-click it, choose Open, then Open again. On macOS 15 and later, if there's no Open button, open it once, then choose Open Anyway in System Settings, Privacy & Security. The first open takes about two minutes to set up the demo.

Version 0.9.2

Release notes

Open Source EOC is an amalgamation of popular emergency management software. It's open source and built for rural and remote local and Tribal governments, where one or two people staff the EOC and a single fire can cut the only fiber line into the valley. It runs on a Windows or macOS computer that the jurisdiction owns, with its own database, and it's built to run with no internet connection at all. Maps, imagery and elevation data are stored on the machine, and field forms can be filled out on a phone or tablet without a signal and sent once the connection comes back. A mobile version is planned for release in the coming week, and FEMA approval is expected soon. It covers the day-to-day work of an EOC: incident boards, ICS positions and forms, and a map-centered common operating picture. It also handles email and SMS notification with contact lists and call-down, reports, damage assessment, resources, JIC review, a record of every change, and federation, so two jurisdictions can share one incident while each runs its own server. It uses the standards EOCs exchange data in (CAP, EDXL, CoT, HAVE and GeoJSON). An IPAWS alert doesn't go out until a second administrator confirms it. It's released under the Apache-2.0 license with no per-seat fees, and read-only viewers cost nothing. A Tribe's records and a county's incident history stay on hardware they control, not in a vendor's data center.

Open Source EOC has no public-facing side. Every record is treated as For Official Use Only, so there's no anonymous map, public dashboard or citizen intake form. Mutual-aid partners get in through a guest grant that expires. It runs as one server process against one database rather than a load-balanced cluster. It doesn't connect to live outside data such as FEMA flood zones yet. Version 0.9.2 is an evaluation build. Everything proven so far was done on the project's own machines with synthetic data, and live IPAWS, a load test on real deployment hardware and a first pilot jurisdiction still haven't happened. What a small Tribal or county EOC gets today is an operations center it can install, own and run without a contract or a connection, along with a written record of what has been tested and what hasn't.
