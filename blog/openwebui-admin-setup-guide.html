OpenWebUI for Administrators: Multi-User Access, Permissions, and Conversation Controls

Basho Parks

Updated October 28, 2026: I wrote this against the April 2026 release; OpenWebUI's at v0.12.4 as of October 25, 2026, so the menu paths are a map: pin your version, re-check roles after upgrades.

An on-premise AI system without an admin plan is a compliance problem wearing a nice interface.

OpenWebUI's the standard open-source interface for local language models; it handles user permissions, conversation history, and usage logging without shipping a byte to a cloud platform. Here's the order I run it in with an admin on site; it assumes the hardware's standing, not where it came from.

  1. The first user created becomes the admin, so get there before somebody's nephew does, give it a 20-plus character password in whatever vault your firm already runs, and disable public registration before anything else; I don't leave a site until that's done.
  2. Add each team member under Admin Settings, then User Management, as Admin or User; Admins change settings, Users reach models and can't touch configuration.
  3. Under Models in Admin Settings there's an access list on every model naming who can reach it, so restrict models after the accounts exist; restrict first and the new hire sees nothing.
  4. Set Admin Settings, then System, then Conversation Retention to 365 days for law firms holding litigation-hold capability, 180 for medical practices, 90 for IT support; where conversations carry protected health information, HIPAA means the database's encrypted at rest and you can name every person who reaches the admin panel.
  5. Give the server a static IP and a hostname like ai.yourfirm.local in internal DNS; it doesn't go on the internet, not even for the consultant who asked nicely, so remote staff come in over a VPN.
  6. Run a nightly cron job that backs the SQLite database up to encrypted local storage, keep 30 days of dailies, and don't sync them to S3, Google Drive, or Dropbox; you've got hardware in the building to keep this data off cloud platforms, and syncing the backups hands it all back.
    sqlite3 /root/ollama/web/conversations.db ".backup /mnt/nas/backup/conversations-$(date +\%Y\%m\%d).db"

Which model each person reaches is the one step I won't prescribe from a blog post; it's a Discovery finding, learned by shadowing the people who run the workflow, so for HIPAA, FERPA, or SOC 2 obligations, reach us and we'll map the access with you on site.
